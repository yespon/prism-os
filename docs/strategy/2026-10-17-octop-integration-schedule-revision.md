# Octop 全量集成排期修订

**日期：** 2026-10-17

**依据：** [批准的能力路线](../superpowers/specs/2026-08-08-prismos-capability-roadmap-design.md)、[全量能力与规划一致性复核](./2026-10-08-octop-full-capability-roadmap-review.md)、[M1 门禁记录](./2026-09-25-m1-exit-gate-evidence.md)

## 1. 修订内容

相对 2026-10-08 建议文档，本文正式确认以下修订：

1. **交付顺序**：从原 Capability Roadmap 的串行 M1→M7 改为产品闭环驱动的纵向交付（R0–R6），平台契约与验收同步完成。原路线的能力目标、退出门、兼容要求与 C1/C2 条件投资全部保留，作为各 R 轮次的收口内容而非启动前置。
2. **目标范围**：全量等价 Octop 当前公开能力 **O01–O42**（固定 b6 基线、77 个路由模块）。F01–F12 官方未来方向及上游 b7+ 新增能力进入增量目标清单，按 §6 节奏吸收，不扩入当前承诺。
3. **容量模式**：人力按需最大支撑、进度第一优先级；任务按 §2 六角色编制拆分到具体 Owner。
4. **并行规则**：初期不设能力迁入并行上限；唯一软约束为单迭代最多一条线触碰 `app.platform` 核心契约。
5. **排期承诺**：R0–R6 从候选窗口升格为正式排期，附三个对外承诺锚点（§4）与 R0 重估条款。

不修订的内容：M1 收口优先级不变——**R0 内 M1 五门不通过，R1 编码不启动**（Q5/Q15 裁定）。全量追赶不得以推迟 M1 收口为代价换进度。

| 锚点 | 承诺 | 前置 |
| --- | --- | --- |
| +6–10 周 | 首个试用闭环：专家 + 私有知识 + 可追踪任务 | M1 退出 |

## 5. 治理规则

### 5.1 门禁仲裁

进度优先，但四类安全反例任何情况下不可跳过（Q18 裁定）：

1. 跨租户访问；
2. Secret 泄露（进日志/Prompt/普通 API/模型上下文）;
3. 副作用重复提交；
4. 审批/授权绕过。

非安全类（UI 打磨、性能优化、次要目录覆盖）可记技术债延后，按既有"每迭代约 20% 回归容量"吸收。禁止以"已复制目录/路由数/页面数"宣告完成。

### 5.2 依赖冲突预授权（Q16 裁定）

Octop harness 与现有依赖（`langgraph-sdk`、`langchain-ollama` 等）冲突时，迁入工程师按以下规则自行处置，不逐次上报：

- 冲突可通融（版本范围可放宽）→ 就地解决；
- 冲突不可通融 → 自动隔离为独立能力 Worker（独立 venv/进程，经协议对接 Gateway）；
- **禁止**为迁入单个模块升级/降级 `app.platform` 及核心依赖版本；平台 Owner 保留否决权。

### 5.3 上游同步（Q8/Q20 裁定）

固定 b6 基线，日常不追 main。每四周复核上游增量；复核发现的新能力只进"待吸收清单"，待当前轮次闭环后评估，不中断当前轮次。上游 b7+ 新增能力与 F01–F12 同等处理：增量目标，不扩当前承诺范围。

### 5.4 质量保障四层（Q19 裁定）

| 层 | 落点 |
| --- | --- |
| 提示层约束 | Skill/专家模板 prompt 规范；迁入内容先过审 |
| 本地门禁 | `scripts/test-platform-contracts.sh` 扩展为分层门禁（契约/相邻/完整回归按改动范围触发） |
| CI 矩阵 | 单任务 CI 扩为四条 job：后端 pytest + 前端 lint/typecheck/test/build + 迁移升降级 + 契约门禁 |
| 测试架构 | 双层验证：模块行为回归 + PrismOS 治理回归；改写上游测试必须记录实际通过范围 |

CI 扩展为 R0 第 6 项任务，由集成/部署验证角色承担（见实施方案）。

## 6. 增量目标清单

F01–F12 与上游 b7+ 新增能力按 2026-10-08 建议文档 §6 的优先级节奏处理，作为增量交付清单跟踪，不进入本轮 24–36 周承诺。逐项吸收仍需满足各自依赖（原生移动等上游代码可得性、公共市场的运营容量等）。

## 7. 验收与完成定义

沿用 [全量复核 §7](./2026-10-08-octop-full-capability-roadmap-review.md) 的验收与差距记录规则，不变：

- 发布账本逐项跟踪 O01–O42 子能力（来源版本、现状、目标路径、Owner、证据、缺口）；
- 九组对标场景全部有成功/拒绝/恢复/故障证据；
- 现有 PrismOS 能力不回退（Slack/K8s/AIOps 等存量路径保持可用）；
- 原平台最终能力和硬门（四道基本门、M3 Evaluation 门、专项 Security 门）通过。
