承接删除候选 `b552fb1` 与同租户 Agent 写入/删除事务协调实施。事务协调只能固定管理写入的顺序；不能将名称列表升级成具体来源绑定，也不证明运行前授权。完整 C2/N09 和原 PrismOS 范围保持。

## 当前事实与接入位置

`CustomAgent.skills` 是原 JSON 名称列表，已有 `metadata` 保存原 Agent 展示与 Octop 来源；不要另建资源注册表。Agent 创建/更新/共享在原 CRUD 事务中修改这些原事实。当前普通图构建使用 `load_agent_config` 的 LRU，再将名称集合交给 `get_skills_prompt_section`；原 Skill loader 按名称合并，公共同名优先，个人资源未按已选实例解析。显式单 Skill 提示又按列表首项注入主文件内容。告警自动诊断和人工诊断也传入名称列表。原一次性执行 capability 核对 tenant/user/thread/Agent，不能据此认定 Skill 实例、当前位置和当前使用权限已验证。

因此下一次实施同时覆盖以下原入口：

- 原 Agent 创建、编辑、共享 UI/SDK 与原 CRUD；具体来源选择、原 metadata 配置和旧名称的明确状态。
- 原 Agent 管理中的删除引用计数；具体绑定只阻止其绑定实例，无法归属的旧名称不能被推断为某个来源。
- 宿主 runtime adapters、原 AgentConfig、图构建与 Skill 提示；绕过旧名称合并、首项选择和缓存来核对已选具体实例。
- 告警自动诊断、人工诊断及指定单 Skill 的原执行入口；共同复用原授权与受控执行路径，不新增执行事实或旁路批准。

## 实施约束

1. 明确选择包含名称、scope 和当前 resource_id；实例 ID 不是内容摘要、权限或执行授权。保留原名称列表可读与旧客户端契约，不自动将旧名称或同名公共源绑定到具体实例。提供旧引用检查及用户重新选择流程；不能仅禁用执行后宣布能力完成。
2. 使用原 metadata 保存版本化的选择配置并与原 Agent 行同事务保存；保留展示/人格/上游来源字段。旧字段更新不得丢失已确认选择，不得悄悄绑定新同名实例。共享 Agent 不能携带创建者个人资源给其他成员；共享/取消共享须按目标范围重新核对。
3. 创建/更新与删除使用共同事务协调；核对原 native 登记的 generation、tenant/owner、规范目录和公共实际来源。别名、缺文件、旧实例、跨用户/租户或被撤回目标拒绝确认；禁用资源可以作为待启用配置保存，但运行时不能因此获得使用权。重试未知操作不能另建注册表或执行记录。
4. 原已选具体引用在使用前重新查当前登记、启停和权限，确认 Agent 当前可用、资源当前位置/成员和使用者身份。撤回、重建同名、撤权或异常位置不得回退到公共同名或其他目录；缓存只能缓存不影响授权的材料。主文件、说明、摘要与注入内容应来自同一已核对读取，不能核对后再按不受保护的路径重新读取。
5. 原默认/空列表语义须从实际 UI、文档与运行契约一致核对，不能借新增引用字段无意缩小默认能力。明确选择零项、所有当前授权资源和旧名称待确认要区分。引用确认不自动安装工具、开启 Agent、委派或批准外发。
6. 同名不同来源在实际编辑界面保持可区分；晚响应、租户/会话切换、关闭重开、未知保存和共享转换须保持已有隔离规则。给出当前检查结果与可完成的重新选择操作，不能只给不可解除的阻断提示。
