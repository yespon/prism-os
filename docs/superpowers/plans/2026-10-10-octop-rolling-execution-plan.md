## 2. P0：来源修正与真实环境收口

### P0-A / N05-A：修正交付归档及资源清单

发现的具体范围：

- 主仓 `src/octop/infra/agents/experts/library/office-automation/skills/{docx,pdf,pptx,xlsx}/LICENSE.txt` 含独立复制/分发限制；四个子树共 186 个文件。
- Harness 英文 PowerPoint 子树 50 个文件已从新候选保留归档排除；中文 PowerPoint 仍有 1 个 `SKILL.md`，frontmatter 明确声明 Proprietary，需要一并处理。中文条目未附独立 LICENSE.txt，不能据包级 MIT 推断其可直接交付。
- 主仓原始归档和已迁入内容仍包含上述 Office 资源；仅排除外部英文子树尚未覆盖全部交付面。

实施：

1. 核对主仓、四包全部独立资源声明，按明确子树形成 exclusions 与路径/摘要证据；保留允许交付的源码、根许可证及版权声明。
2. 主仓提供过滤后的源码视图，分别记录原上游 commit、原始归档摘要、保留归档摘要和成员摘要。不得把过滤归档摘要写成原发行摘要；不得修改允许保留的原样文件内容。
3. 同步更新 `scripts/octop_sync.py`、`octop_external.py`、`octop_inventory.py`、能力包 provenance、wheel 校验和候选升级探针。原 source_files 摘要可保留为来源收据；实际保留文件/迁入文件数量独立计算。
4. 仓库当前交付文件、外部归档、sdist/wheel 和构建产物都排除受限资源。保存原文件摘要及原因，避免重新下载、候选升级或打包时回流。既有 Git 历史不在本批重写，任何公开发布前应核对其是否仍携带该材料。
5. 为 DOCX/PDF/PPTX/XLSX 和双语 PowerPoint 建立独立实现条目，继续映射 O05/O07 等原能力；能力状态保持 remaining，进入 N09 资源切片。替代实现依据公开格式和允许使用的工具设计，逐项验证创建、读取、编辑、导出等原用户路径。

验收：保留文件与来源收据逐字节一致；已知受限子树不进入任何候选交付制品；修改 exclusions、来源摘要、资源缺失或归档内容均触发失败；专家/人格目录原用户路径可用，配套资源缺口可见；来源校验、相关行为回归和制品构建通过。以真实字节和能力账本证明修正，不以删掉能力条目减少范围。

### P0-B / N04：使用已有测试环境收口 M1

用户已选择使用已有测试环境。仍待环境位置与现有配置引用，选择本身没有提供连接信息，也不表示已完成部署授权或验收。需要 Gateway/LangGraph 地址或部署目录、数据库配置引用、模型配置引用、隔离租户/请求者/管理员，以及可核对调用次数与幂等键的测试工单接收端；使用现有 Secret 引用，文档和消息不记录密钥值。

信息具备后按 [M1 目标部署验收顺序](../../strategy/2026-09-25-m1-exit-gate-evidence.md) 实施：

1. 固定待验 commit、配置及数据库 head，先预检和备份；对已有数据先 dry-run，核对有界 apply 范围。
2. 验证真实认证会话经过 Gateway/LangGraph 传播，在服务端启用严格图上下文；先保持 Action 开关关闭。
3. 仅在隔离测试租户验证 deny、require_approval、allow；核对实际模型 Tool、Policy、Approval、Audit、Submission 和接收端调用次数。
4. 验证轮换/禁用/撤权/旧批准、跨租户、关键 Audit 故障、重复请求、超时 unknown、重启与投递恢复；unknown 先核对外部事实，不能自动重发。
5. 演练开关回退、部署回退与数据库备份恢复，保留历史事实；非空 Secret 表不执行破坏性降级。
6. 分别裁定 Contract / Golden / Quality / Migration / Security 五道门，记录请求 ID、环境、commit、通过/失败/跳过和证据。全部所需门通过才宣布 M1 退出。

## 5. 持续吸收上游的实施要求

当前 b5→b6 升级证据覆盖目录/人格，尚未证明 Knowledge、Teams、Schedule、Browser 等耦合模块能持续吸收。后续每个首次接入的耦合模块，都要配套完成至少一次有实际变更的候选升级与回退试验。

1. 固定主仓 commit 和四包精确版本；分别记录原样源码、必要补丁和宿主 Adapter，业务身份、执行事实、Secret、Policy、Audit 与 Artifact 由 PrismOS 拥有。
2. 内容和允许使用的纯算法可以批量吸收；依赖/schema/副作用/协议变更走对应评审和行为门。现有 MCP Adapter 约束冲突先评估选择性迁入或版本化能力 Worker，不直接改宿主锁文件，也不据冲突自动启动 C1。
3. 为 Worker 冻结请求/事件/错误协议、tenant/actor 与资源引用、超时/取消/unknown、权限和凭据注入边界；安装成功不能代替治理兼容证明。
4. 上游候选 diff → 独立候选工作树 → 许可/来源/权限/依赖差异 → 上游行为与宿主双层回归 → 数据/副作用/设备验证 → 制品替换/回退 → 账本更新。
5. 每次记录新能力、不可直接复用部分、补丁数量、首次与升级工时、运行证据和剩余项；用真实维护成本更新尾部估算。未来方向是否与原规划一致，由 O/F→原 M/C→接缝/门的逐项映射判断，不用方向名称相似替代实现核对。

每个可交付提交保持可运行并附验证证据；每两周验收一条用户闭环，每四周安排一次固定版本的上游复核。这是工作节奏，没有创建自动监控或承诺后台持续运行。无法通过的候选不晋级；制品回退与数据库回退分别执行，保留已记录事实。
