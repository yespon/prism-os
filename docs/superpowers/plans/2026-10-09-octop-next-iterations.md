## 2. 推进原则与依赖

实施主线为：**整合基线 → M1 凭据/部署收口 → 持久执行最小闭环 → 专家资源完整使用 → 私有知识与连接器 → 自动化与团队 → 工具/多端/完整生命周期收口**。

M1 未退出时可以做静态目录、人格体验、来源/依赖盘点、增量设计和构建验证；不实施或启用 M2 持久生命周期。真实环境若尚未就绪，继续这些独立任务，M1 退出与依赖它的任务保持待验，不能用 mock 替代后启动 M2。

M1 退出后按用户已要求的纵向交付方案，在每个切片的增量 Spec 中冻结必要的执行、版本、Secret、资源和治理接缝。完整 M2–M7 能力与正式退出门仍逐项完成；提前交付一个快照、单任务调度或知识 API 均不等于对应整个里程碑退出。保留原 Slack、Kubernetes、Terminal、AIOps、模型、文件和 Skill/MCP 路径。

原样上游文件、必要补丁、宿主 Adapter 三者分开；新增模块只加入已经验证的依赖组合。四个外部 Octop 包单独盘点，不能直接安装 `[all]` 或替换原 DeerFlow/LangGraph。冲突时按能力 Worker 和版本化协议评估，业务身份、执行事实和治理仍归 PrismOS。

## 4. 后续四个交付切片

下列时间是相邻主线切片的预算，从依赖门通过后起算。能力包内容和前端独立任务可交错，不能假设全部并行来压缩总工期。8–12 周只用于首个试用闭环的容量核算，不承诺全部 Octop 等价或完整 M2–M7 退出。

### N08：可追踪、可恢复的单 Agent 执行（候选 2–3 周）

启动条件：N04 形成 M1 退出证据；M2 增量 Spec/状态机/迁移与兼容设计完成。修改面为 `app.platform` 契约、持久模型/Repository、唯一 Alembic 链、Gateway LangGraph 代理、原 runtime adapter、前端执行状态投影。

- 从 Web/API 单入口落地 Task→Run→Attempt→Action→Event，固定 tenant/actor/Agent、模型、prompt、Skill/MCP 和资源引用；快照不含 Secret，旧线程有明确绑定与兼容规则。
- 先实现启动/流式/完成/失败/待审批/恢复/取消、有限重试与幂等；取消必须传到底层执行，记录未确认取消的真实状态。重启/失联检查 checkpoint 与外部提交事实，不把 unknown 转成成功或自动重试。
- 对 Runtime 使用实际支持的 start/stream/pause/resume/cancel/get_state 接缝；不支持项明确报错，契约可渐进冻结，M3 全量 Runtime/Evaluation 仍单独退出。
- 验收：刷新/重启不丢事实、重复入口仅一个 Run、并发 cancel/resume 正确、跨租户/撤权拒绝、运行中编辑 Agent 不改变本次配置、老聊天和 AIOps 可用。

### N09：专家、子智能体和配套资源可完整使用（候选 1–2 周）

依赖：N05–N06；引用到执行的绑定依赖 N08。复用当前内容包、CustomAgent、Skill/MCP 安装路径，先补最小资源声明和来源 digest，不提前宣称完整 AgentVersion/市场供应链完成。

- 区分资源拥有、共享可见、复制、使用、编辑、撤回；明确复制快照与实时引用不同语义，共享不包含私有会话和凭据。
- 支持专家依赖预检、按清单安装/绑定授权的 Skill/MCP、子智能体成员选择和使用；配套脚本逐项纳入工具/schema/执行 PEP 和隔离，失败恢复不留下半安装资产。
- 验收：至少两个有实际配套资源的专家、一个子智能体委派路径可运行；同租户成员使用、管理员编辑/撤回、跨租户拒绝、升级/复制来源固定通过。18 个专家逐个对照清单，不以代表样例替代全目录验收。

### N10：私有知识问答与两个参考 Connector（候选 2–3 周）

依赖：N08 的执行/来源关联；冻结通用 Secret、Document/Chunk/IndexVersion 与 ACL 增量契约；先从上游归档提取知识算法/解析/检索/引用，再用宿主 Repository、Storage、身份和后台任务适配。四个外部包的相关依赖组合需 N05 实测。

- 首个无外部凭据的闭环为租户文件上传→解析→索引→检索→带引用回答→删除/撤权。明确索引版本、重建、失败恢复与受保护 Artifact，查询前检查当前文档权限。
- 参考 Connector 先选一类公开学术查询（候选 OpenAlex）和一类有认证/刷新/撤销的企业数据源；第二类依据可用测试环境选定，不能用两个无凭据 URL 证明 Secret/OAuth 生命周期。
- 通用 Secret 为目的/资源/租户范围的独立接缝，复用已验证加密基础；不直接把仅限 Source/`ticket.create` 的仓库用于任意 Connector。
- 验收：AIOps 文档问答与企业研究两场景共用底座；撤权后缓存/索引/Worker 不能召回，旧引用不能绕 ACL 读原文；限流/刷新失败可恢复，引用确实对应当前有权访问的文档。两个参考不等于全 Connector 目录完成。

### N11：单任务自动化，再接 AgentTeams（候选 3–4 周）

依赖：N08 持久执行与取消/unknown 语义；N09 成员及资源引用；副作用继续走 M1 PEP。冻结 Schedule/Occurrence/Delivery 与父子 Run 的增量 Spec。

- 先做 cron/date/run-now、时区/DST、停用、missed-run 策略、重启去重和受控投递；Occurrence 唯一触发一个业务 Run，通知重试不重执行业务。
- 再接主持人/成员编排、并行预算、有限递归、成果归并、父子取消/恢复和审批；使用相同 Run/Action 事实，不照搬上游进程内 Job 作为第二事实源。
- 首个有身份映射的 IM 通道复用现有配置，剩余通道逐项验收，原 Slack 保留。自然语言建任务只生成可审阅配置，运行时仍核验权限。
- 验收：定时研究摘要与 AIOps 受控任务各一条；重复触发/进程重启不重复副作用，网络超时 unknown 不盲重发，团队中途撤权/取消有效。该切片不代替完整 M5 Workflow DAG。

| 层次 | 验证入口 / 要求 |
| --- | --- |
| 每次有界改动 | 相关契约/行为回归、`make octop-verify`、改动面 Ruff/类型检查与差异检查 |
| 每批可交付候选 | `make octop-build`；后端完整 pytest、前端全量 Vitest；干净检出与锁定依赖安装 |

| 涉及执行/外发/设备 | 真实模型/目标 Provider 或设备；同租户/跨租户、撤权、审批/取消、超时 unknown 与幂等；mock 只计契约证据 |

现有 `make octop-build` 的 Gateway 冒烟是临时 SQLite + 真实认证/创建/读取，不是 LangGraph/模型/外发执行验收；N04/N08/N10 等必须增加各自完整用户路径。当前工作流已写入但未远端运行，N07 取得远端运行证据后更新状态。

每两周以一条用户闭环验收，每四周按固定 commit 复核上游主仓和四个外部包；这只是实施节奏，本次没有创建自动监控。维护账本记录每个 O/F 子项的状态、来源、支持版本组合、必要补丁、工时及验证链接。内容变更可批量吸收；依赖、schema、工具副作用与协议变更必须经过对应门，禁止原地追 main。

遇到失败时保留最后一个通过验证的候选；回退制品不自动降数据库。连续上游版本使补丁失控或改变核心语义时，重新划分模块/Worker 边界，目标能力继续保留。
