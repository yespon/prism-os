## 第一个可交付切片

先加固现有 personal/tenant import 的文件发布和冲突恢复，再把固定来源包导入接到相同安装服务。复用 TenantSkill 的租户/用户唯一键、原管理员共享写权限与原 personal 目录；不新增第二套 Skill 注册表。安装不自动绑定 Agent、开启脚本/网络/设备或授予 Secret。

1. 核对现有 installer 的 copytree、目录冲突与 API 的 DB 失败清理。在独立候选中重现部分复制失败、同名并发、DB 唯一键冲突和发布后中断；先形成故障矩阵及当前可恢复事实。
2. 定义暂存、发布、注册三阶段。完整包在目标所在文件系统的唯一暂存目录通过原严格 validator、来源摘要和路径边界检查后，再以排他发布方式安装；已有目录无论是否相同都不得静默覆盖。文件系统与 DB 不是单事务，必须明确各阶段中断后的状态与恢复路径。
3. 清理只能作用于当前操作可证明拥有的暂存/发布内容。DB 冲突或超时不能删除其他请求、已有用户资源或无法确定归属的目录；保留可识别的未注册内容，恢复需再次核对身份、源摘要及实际文件状态。重复确认不得产生第二份资源或猜测成功。
4. 对固定上游来源入口重新读取和校验源声明，服务器按当前 tenant/actor 决定目标；禁止客户端传绝对 install_dir、任意文件路径、其他用户目标或未校验来源包。有限三处格式映射、逐成员来源记录及固定上游版权文本继续保留，未知差异返回阻塞原因。
5. 前端提供明确的个人/租户导入确认、同名冲突说明与安装后重新核对；用户主动导入后才改变安装事实。租户切换/关闭/晚响应仍失效，结果不写入 Agent 的执行权限或资源已绑定标志。

验收必须使用真实 installer、SQLite/独立 PostgreSQL 的 TenantSkill 唯一约束及实际文件系统故障；同用户跨租户、同租户不同用户、管理员共享写入、普通成员拒绝、来源更新/篡改、禁用与原目录兼容逐项测试。每次有界变更运行相邻回归；交付候选运行完整前后端、统一构建、独立检出与固定宿主升级/回退。无新 schema 也要明确记录唯一 head 未变化；有 schema 变更则先冻结迁移/恢复设计并走原数据库门。
