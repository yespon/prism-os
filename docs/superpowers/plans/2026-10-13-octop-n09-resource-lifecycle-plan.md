## 下一可交付接缝

先审计原 TenantSkill、personal/shared/public 可见性、管理权限、Agent 已有资源引用、实际文件及 UI 查询身份边界。资源名不能代替具体来源/拥有者/当前权限，列表或旧事实不能作为后续写入/使用授权。保留原姓名冲突、禁用覆盖及 public 默认解析能力。

在原登记与 C1 文件服务上实现明确的复制/分享操作。目标由当前身份和原管理员权限决定；来源必须是当前可读取的具体资源，禁止客户端指定任意绝对路径、其他用户安装位置或用同名 public 回退替代被撤回的来源。先用实际失败重现明确原流程的缺口，再定义变更和验收。

分享/复制不携带 Secret 值、审批结果、历史执行权限或其他用户的 USER/MEMORY 活跃数据；工具绑定等引用在目标范围重新核对。文件与 DB 的中断继续使用已证明的暂存、排他发布和未知保留边界，不建立第二套注册表，不自动绑定 Agent 或获得执行权限。

禁用/撤回先复用原管理与当前 ACL；已绑定/已记录事实可保留历史，但后续使用必须重新授权。删除或回收必须另行证明归属、依赖引用及未知操作边界，不能把禁用等同于递归删除目录或历史事实。

### C2-A 来源审查后的写入顺序

具体来源与身份读取接缝完成最终验收后，按以下顺序推进 C2-B/C2-C，保持原完整资源生命周期范围：

1. 先在隔离 DB/FS 重现旧 PATCH 的重建同名、异常绝对路径、public 文件修改及禁用/撤回后的来源变化，明确当前授权与文件归属。写入必须同时核对原生实例、实际目标目录和当前权限；先得到可审查修复，再接新写入接口。
2. 原 C1 服务上实现复制/分享的预检与明确确认。当前可见的具体来源 id 不能锁定内容，另行核对完整成员摘要；来源改写、撤回、不可核对、角色变化与目标冲突须阻断或进入明确 unknown 恢复，不按名称补来源。目标在当前 actor/tenant 下重新核对，文件/DB 中断仍保留已发布未知内容。
3. 禁用/撤回和旧 Agent 名称引用兼容一起核对。旧名字不能证明已选中的私有/共享实例，也不能把撤回资源默认为同名 public。保留原 public 默认及开关，但明确具体来源/使用前授权；持久快照和委派仍依 N08/M1，当前读取 metadata 不授予执行权。

候选仍执行完整前后端、当前/独立默认构建、实际鉴权与 SQL/文件恢复、固定宿主源升级/回退。C2-A 的读取修复不代表以上写入/使用前授权已完成，不据此退出完整 C2、完整 N09、N04/M1 或远端 CI。
