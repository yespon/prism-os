# N04 部署快照、制品回退与旧审计恢复

沿用 codex/octop-integration / faa28b6，应用源码和当前 b0ee063a 镜像不变。仅新增自有 WSL 栈的私有快照控制器及保护测试，并将其纳入原 CI/固定源码升级门；不推送、发布或启用业务 Action。

## 可用能力及真实验收

scripts/octop_wsl_test_snapshot.py create 在核对专属项目/关闭开关后暂时停止 Gateway、LangGraph 和接收端写入者，保存配置、加密主材料、原 Compose、私有运行目录、自定义 Skill、图本地状态及接收端字节/权限，同时导出三套实际数据库。即使捕获或清单写入失败，finally 仍恢复当前服务。私有目录 0700，归档/数据库/清单 0600，已有快照绝不覆盖。

verify 只向新建专属目录和新建临时数据库恢复；拒绝外部路径、别名、重复/越界/链接归档成员。实际校验所有文件字节与模式、每张表的全部规范化行摘要，随后用原模型工厂验证恢复后的数据库确实被选择、原加密模型凭据可解开；不发模型请求、不导出材料，最后移除临时数据库。目标快照见 snapshot-create.json / snapshot-restore-verify.json，包含三个数据库的表数与行数。

artifact_rollback.py 真实切换上一已验收制品 04eef0d2 和临时关闭态 Policy 版本，再恢复当前 b0ee063a 及原 Compose 字节。各阶段经原 HTTP 登录验证模型可用配置、原已提交工单/时间线、自定义 Skill 身份与文件，以及跨租户拒绝；Action/可信图开关始终 off，接收端调用不增加。上一制品存在已保存的选中 Skill SSE 自阻塞，因此回退阶段不启用该新诊断能力；回退验收范围明确为已有关闭态读取和配置/审计恢复，不宣称旧版具备新修复。

jsonl_failure_replay.py 将本栈原审计文件暂存，建立同名目录触发真实 IsADirectoryError；请求经真实 gpt-5.6-luna、原 Tool/Policy/Approval/Action/Audit 和 HTTPS 接收端。平台提交事实与旧时间线先保存，JSONL 失败进入原可重放表。恢复原文件后两进程共八次原服务重放只产生一条 JSONL 事件，重复恢复不重发工单，接收端 25→26。原审计文件和 off 开关均恢复。文件故障作用于独立测试项目审计文件，不把它描述成按租户隔离的文件系统故障。

protected_downgrade.py 在实际快照的独立克隆库上使用原 Alembic 降级入口检验非空 SecretRef 保护，核对拒绝前后所有行内容；只按其实际退出码/完整业务断言裁定，不对当前库做降级。

## 验证与边界

新增测试覆盖私有文件不覆盖/权限、外部目录和别名拒绝、归档穿越/链接拒绝、磁盘故障时恢复服务、外部数据库配置拒绝。当前默认权限无网络镜像和固定 b5→b6→b5 升级门新验收；应用/前端/来源/依赖等仅按 historical-reuse.json 的精确未变输入复用，不重复全量或重建应用。最终结果、原始日志 SHA、当前运行状态和公开证据凭据检查见 validation.json。

快照材料和恢复目录始终在忽略的 backend/tmp，实际模型/接收端凭据、数据库行值、配置内容、服务日志与模型原文均不进入公开证据。原脚本早期静态检查和实际失败如有，均保存不改写。

文件/全表克隆验证和模型工厂通过，仍不能替代“从恢复快照启动整套服务、运行全部原用户路径”。该项与其他文件/工具入口完整复核、原五道门最终裁定和 N07 远端 CI 继续保留；M1 未退出、N08 不启动，所有原 N/O/F 和 PrismOS 目标不变。
