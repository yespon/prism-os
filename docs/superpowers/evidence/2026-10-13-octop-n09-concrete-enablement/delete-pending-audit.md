# 旧删除/手工创建接缝：当前候选未修复的真实故障

本审查与启停 17 个冻结输入分开；下面三个隔离探针断言所需保留条件，当前实现不满足并产生实际失败，证明完整 C2 尚未达成，不纳入启停绿色验收计数。输入及实际日志见 [probe](logs/delete-pending-probe.py) / [log](logs/delete-pending-faults.log)。运行方式：从 backend 使用 `PYTHONPATH="$PWD/tests:$PWD" uv run --locked pytest <probe绝对路径> -q`，仅操作夹具创建的 SQLite/临时目录。

| 请求 | 当前实际状态 | 下一批要求 |
| --- | --- | --- |
| 当前用户按名 DELETE，附已失效 expected_resource_id | 返回 204；当前目录已删除，原生行由 2 减为 1 | 锁定并核对当前拥有者实例；旧选择不能删除重建同名资源 |
| 当前用户按名 DELETE 已由原 C1 服务发布、收据可检查但尚未登记的目录 | 返回 204；目录已删除，原生行仍为 2 | 404/冲突并保留未证明归属的发布内容，不能猜测失败导入应回滚 |
| 手工 POST 创建同名 C1 已发布未知目录 | 返回 201；原主文件字节被覆盖，原生行由 2 增为 3 | 创建与原 C1 排他发布/登记接缝统一，不能把未登记理解为允许覆盖 |

当前代码还在服务提交后按计算的名称目录递归删除，未核对登记中的实际目录、完整文件成员、原导入收据、旧 Agent 引用和未知结果。后续应先重现共享/public、异常位置、目录替换、角色撤回与引用情况，再确定明确的撤回/物理回收、恢复事实和用户确认；不能以仅禁用或保留目录代替目标要求的完整生命周期。

第二/三项通过原 prepare/publish 服务真实排他发布，并在删除前通过原检查 API 核实未登记；不是假设一个空目录就是失败导入。原 C1 安装/恢复服务回归通过，只证明已验收服务接缝，不证明所有管理入口的保留边界均已加固。

本批启停不改变这些 DELETE 接缝。复制/分享与完整成员来源、目标重授权、旧 Agent 名称引用及撤回后的使用前授权继续保留；完整 N09 与原 PrismOS 目标未退出。
