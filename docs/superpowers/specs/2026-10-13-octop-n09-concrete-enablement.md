基线 `52e3cf3`。完成原 PATCH 条件编辑后，先加固原 PUT，再继续删除、复制/分享和使用前授权；不把一个开关接缝替代完整生命周期。

## 已重现的问题

真实 SQLite/文件系统重现四项原失败：忽略过期 expected_resource_id 后修改同名行；选择 public 实例却改变同名 custom 行；未知名称生成无来源登记；异常安装目录仍改变记录。当前可见列表、资源名和平台角色不能替代当前租户管理员授权。

## 实例、位置和原生覆盖

PUT 增加可选 expected_resource_id；保持原 enabled 请求及成功字段，响应补充具体 scope/id/主文件状态。当前租户管理员权限与当前 actor 必须在服务调用前核对。PostgreSQL 行锁或 SQLite BEGIN IMMEDIATE 下选择原 TenantSkill。

当前非 public 原生行按登记代际 id 核对，目录按现有 owner/tenant 解析且拒绝别名和跨所有者路径。启用要求主文件存在；缺主文件仍可禁用该已证明归属的记录，避免强制保持启用。目录无法核对时拒绝修改，留待独立修复，不改写旧元数据。

明确 public 选择只读取固定 public 库中的该具体相对路径；已移除来源不按同名回退。需要建立覆盖时使用原 shared owner/name 行和原 category=public；不创建第二套注册表。现有 custom 同名占用原唯一键时返回 409，不修改/转换 custom 或取消唯一约束。既有 public 覆盖的路径也须匹配当前来源。不同租户的启停互相隔离，public 原文件不变。

旧不带条件的按名调用先选择当前拥有者原 shared 行，否则选择唯一当前 public 来源；未知名称 404，歧义 public 名称 409。该兼容语义不证明跨请求同一实例。个人项沿用已完成的原 PATCH，不通过共享 PUT 修改。

## 未知结果与用户流程

原行提交、提交后响应及详情读取可能不确定：返回 503 与 resource_id/inspection_required，保留实际状态，不自动补偿或重复提交。前端捕获当前身份，在异步取得鉴权头后、派发前再次核对；旧完成响应不刷新新身份缓存或显示旧结果。
