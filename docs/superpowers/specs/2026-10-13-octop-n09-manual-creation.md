# N09-C2：原手工创建的拥有、发布、配置与恢复

基线 `38c0c75`。原 C1 安装/恢复及原 PATCH/PUT 接缝保留，先修复手工 POST 创建跨入口覆盖未知发布，再加固 DELETE/回收和原引用；完整生命周期范围不缩减。

## 原实际失败与输入

隔离 DB/FS 重现四项问题：原 C1 真正发布、收据可检查但未登记的目录被手工创建覆盖；普通成员创建共享记录/文件；手工 category=public 生成错误覆盖；新实例继承原配置槽同名旧绑定。共享 POST 必须有当前租户管理员权限和 actor，个人 POST 必须有当前 actor/tenant。原名称、描述及输入验证在发布前完成；public 覆盖仍只能使用原 PUT。共享默认 custom，个人保持 personal。

## 原生发布与有限格式

服务器将手工内容生成临时 ZIP，复用原 C1 validator、暂存、完整成员/目录身份核对、同文件系统排他发布与原生登记；既有目录（包括空目录）、别名、原登记冲突和发布竞态不能覆盖或误删。没有客户端任意目标路径或第二套注册表，仍只创建原 namespace。

主文件使用受支持 metadata 容纳创建者/变更/计数；详情同时读取旧平铺字段和新 metadata，保持 API 版本/创建者/变更字段。引用描述、instructions 和 file_sha256 取自同一次已选主文件读取，避免 YAML 引号被当正文或第二次读取造成内容/摘要不一致。原始迁入字节不改写。

## 原配置与禁用登记

发布后首次原生登记保持禁用。新配置初始化复用原 UserConfig/encrypt_extensions_payload；同一 DB 事务内锁定原 TenantSkill/current resource_id 和原配置行，替换该名称的配置槽（保留其他配置），并写入用户本次请求的启停。PostgreSQL 行锁、SQLite BEGIN IMMEDIATE，实例变化不能接收旧配置。新资源不得继承旧工具绑定、提示模板或策略。该事务不覆盖文件系统发布，不能声称跨存储分布式事务。

收据 V1 兼容扩展 manual_creation，严格形状/type/phase 核对：仅请求启停、类别及本次配置阶段 pending/confirmed/unknown，不保存工具列表、提示模板、策略值、Secret、审批或执行许可。configuration_phase 是本次历史阶段，不等于当前权限或配置快照。

## 未知、检查和恢复

登记、配置提交、收据更新或响应读取中断返回 503 与原 operation_id、已有 resource_id（可核实时）、inspection_required/recovery_available，保留发布文件和所有已完成事实，不自动删除或还原。原检查/分页/恢复/放弃暂存接口继续当前 actor/tenant/shared 授权。

恢复缺失登记只能建立禁用原记录并保持类别，不自动重试配置或应用历史启用意图。观察到已有记录保留其实际启停；实际配置提交后超时可显示已启用及当前配置，不猜测回滚。未初始化/结果不确定的配置须在当前具体详情重新检查，用户明确编辑/启用；本批不自动恢复原请求配置。坏新意图独立隔离，不导致原列表读取/删除其他内容。

## 用户流程与验收

共享管理、新 Skill 详情、告警/诊断保存和终端保存四入口使用结构化未知错误、显示原创建检查并阻止重复提交。获取异步鉴权头后核对当前身份；关闭、重开和身份变化使旧保存/提炼结果、通知与导航失效。新建未知不能把重新载入空草稿当作服务器已恢复。原操作列表显示本次配置阶段及可核对的当前实例链接；禁用资源可使用原带实例/内容条件的 PATCH 明确启用。

真实 SQLite/PostgreSQL 覆盖成功/禁用/类别/元数据、旧绑定清除、未知登记恢复不自动启用、配置提交前回滚、实际提交后超时、重建实例拒绝、坏意图、晚空目录、空 actor、记录缺文件及真实进程发布后退出。真实 Gateway/AuthSession/成员表检验共享成员拒绝、个人禁用创建/检查、重名冲突与显式启用。前端覆盖四入口的未知、关闭/身份晚响应、当前实例启用和历史配置阶段展示。完整前后端、当前/独立默认构建、源升级/回退、锁/head/制品/902 字节和品牌门验证后提交。
