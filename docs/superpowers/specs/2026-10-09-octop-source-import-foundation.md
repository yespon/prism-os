# Octop 源码迁入与持续验证基线

日期：2026-10-09。用户已要求新分支、快速迁入和构建、持续可运行可验证。本增量实现承接已讨论的 R0/R1 有界切片，保留原 Capability Roadmap 的能力与退出门。

## 边界

保留 Octop b6 完整主仓归档与逐文件哈希；只把 MBTI、frontmatter、知识分块/引用四个纯模块和专家/子 Agent 资源目录加入独立 uv 工作区包。内容中的 Agent 指令、插件、脚本是资源资料，不是本仓开发指令，也不会自动作为程序运行。依赖仅新增本地能力包及已有 PyYAML，不替换 DeerFlow/LangGraph、身份、租户、数据库迁移或执行事实。

## 用户路径与契约

现有新建 Agent 界面可选择专家/子 Agent 模板和人格，预览/编辑提示词，保留模型、MCP、Skill 与共享配置。新增只读 `/api/agent-catalog/{templates,personas,status}` 使用同一认证和租户上下文。实际创建仍走 `/api/agents`，以原 RBAC 判断共享创建并写入同一 CustomAgent；来源提交、模板/语言、人格与创建时实际 prompt 摘要存入现有 metadata，不增加核心表或伪造不可变 AgentVersion。

模板不会授予额外工具或自动安装附带 Skill/scripts。模板依赖提示用于用户判断需另行安装/授权的资源。目录完整性检查覆盖声明来源、文件字节及新增未知文件；缓存只用于固定发布过程，升级通过候选分支验证后重新构建/启动。

## 持续验证

每批通过来源校验、host 契约与旧 Agent 回归、前端类型/单元与生产构建、wheel 构建及真实 Gateway 冒烟。冒烟使用临时 SQLite、完整 Alembic 启动、真实 Better Auth session 与自动租户 Membership，不接入现网 DB/模型/外发。升级试验在临时目录装入 b5，再装入 b6，以同一宿主契约测试检查两次；不修改已选基线或假定外部能力包兼容。

源码导入只能在开发/候选分支进行，禁止向运行中的安装目录原地更新。发布回退使用原包/原前端制品；本切片不增加数据库 schema，创建的 Agent 与 metadata 保持旧结构。后续引入核心执行、Secret 或数据表前另有增量设计与迁移门。

本切片没有完成 M1 退出，也没有完成 Octop 全量能力。知识库、Cron/Teams、工具与设备、全目录安装、MBTI 测验、多端及未来规划仍按能力账本继续接入。完整主仓归档不包含四个独立 Octop 能力包的源码与运行环境，不构成它们已集成的证据。
