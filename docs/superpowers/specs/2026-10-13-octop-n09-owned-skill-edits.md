# N09-C2：旧 PATCH 的自有条件修改

基线 `ea843bd`。在具体来源与当前身份读取之后，先加固原 PATCH 写入接缝，再推进完整复制/分享/撤回。TenantSkill 与原加密配置仍是事实来源；没有新表、注册表、执行事实或自动资源授权。

## 实际故障

隔离 DB/FS 与 HTTP 重现：普通成员修改共享项先更新登记再失败；个人登记指向另一用户目录时覆盖该文件；public 修改先改变原租户覆盖再失败；过期资源实例条件被忽略。共享方法还把 description 字符串当作前言 dict 使用。四项失败保留，不将未完成的写入当作成功或声称已回滚。

## 授权、实例、内容与位置

共享 PATCH 强制原 require_tenant_admin，个人 PATCH 必须有当前 actor/tenant。服务从当前拥有者+名称查询原生行，锁定行后核对可选 expected_resource_id；原有创建/拥有者代际标识继续使用。提供条件的请求不因同名重建选择新实例；旧未带条件的按名调用保留“当前拥有者范围的当前名称”兼容语义，不能据此证明跨请求同一实例。

修改不能把资源重新归类为 public，也不能通过 PATCH 改 public 源或覆盖记录；原 tenant PUT 启用覆盖入口保留。任何类别/身份/实例/目录/前言/描述拒绝必须在原生状态和主文件改动之前发生。当前共享前言 created_by 不构成授权，当前管理员权限是最终判据。

目录只由当前拥有者范围解析，不接受其他用户路径或文件系统别名。打开目录及主文件时使用 no-follow 描述符，核对实际目录和主文件身份；主文件要求普通文件。描述/指令/前言/版本验证后准备同目录唯一临时文件、fsync，再核对目录和主文件身份/字节并原子替换。被替换的目录或后来修改的主文件不按原操作内容覆盖/删除。临时清理仅通过仍持有的原目录描述符作用于本操作的唯一临时文件。

详情及可编辑列表返回其读取主文件字节的 file_sha256。可选 expected_file_sha256 防止旧表单覆盖同实例后来编辑。前端个人/共享编辑传递已读取实例和摘要；新旧基本成功字段保持，PATCH 响应补充实例、摘要、版本及 scope。

## 事务和未知结果

PostgreSQL 使用原行锁；SQLite 使用 BEGIN IMMEDIATE，串行化参与原生 DB 的该次修改。权限/实例/目录/输入全部验证后才改变文件和原生行。原配置更新继续使用现有服务，没有第二套保存位置。

文件系统、原生 DB 与配置更新不是一个分布式事务。文件已替换后的中断、实际 DB 提交后的响应超时、配置更新不确定及成功响应读取失败统一要求 inspect current state，携带当前 resource_id；不能自动还原旧字节、删除文件、重复提交或猜测 DB 回滚。当前具体详情可核对文件/版本/原生状态与配置。此读取检查不执行自动补偿，不声称完成持久执行事实或跨存储事务。

本批保护当前应用的行锁/目录与文件检查边界，不声称对不遵循同一协议的外部文件写入提供跨系统锁。无法提供安全描述符原语的文件系统拒绝编辑并保留内容；实际验证在当前 Linux 文件系统完成。

## 用户流程

错误协议保留 message/resource_id/inspection_required。403/401 是当前权限拒绝，409 是实例/内容/位置冲突，503/网络中断提示重新检查。个人详情和共享编辑未知/冲突后阻止重复保存，明确重查当前具体详情/列表，不将中断理解为服务器回滚。原界面生命周期和身份查询缓存边界保持。
