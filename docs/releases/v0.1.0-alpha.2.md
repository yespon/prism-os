# PrismOS v0.1.0-alpha.2

**Status:** Pre-release / alpha  
**Release tag:** `v0.1.0-alpha.2`  
**Repository:** <https://github.com/yespon/prism-os>

PrismOS is a governed Agent operating system foundation for enterprise teams.
This alpha follows `v0.1.0-alpha.1` with a corrected frontend dependency lockfile
and a clearer separation between runtime publication gates and the frontend
quality-debt audit.

## Why this release exists

The `v0.1.0-alpha.1` publish workflow stopped at its validation job because the
tracked `frontend/pnpm-lock.yaml` still contained importer specifications for
AI SDK packages that had already been removed from `frontend/package.json`.
That produced `ERR_PNPM_OUTDATED_LOCKFILE` under `pnpm install --frozen-lockfile`
and prevented the backend/runtime image from being published.

Alpha.2 synchronizes the lockfile with the current package manifest. The
following installation paths were verified locally:

```bash
cd frontend
pnpm install --lockfile-only --ignore-scripts
pnpm install --frozen-lockfile --ignore-scripts
```

The release tag is the immutable source reference for this version. The
corresponding Actions run is the source of truth for the published image and
its commit SHA.

## What is included

The platform capability baseline remains the same as alpha.1:

- multi-tenant user and resource scopes;
- platform and tenant RBAC with protected management routes;
- database-backed model/provider configuration and tenant assignment;
- scoped Skill management, import, editing, and sandbox testing;
- tenant-scoped MCP configuration and health checks;
- local, Docker, and optional Kubernetes sandbox adapters;
- thread files, uploads, generated artifacts, preview, and download;
- user, tenant, announcement, audit-view, and administration surfaces; and
- optional vertical plugin surfaces for alerting, terminal, and assets.

Agent management, plugin SPI, runtime abstraction, and a unified audit model
remain partial foundations. Policy, Task/Run lifecycle, Workflow, Evaluation
and observability, Connector federation, runtime independence, and
cross-organization Federation remain roadmap work; this release does not
present them as completed platform contracts.

AI operations remains an optional validation scenario, not a dependency of the
PrismOS core architecture.

## Runtime and container publication

The complete local application is assembled by the repository's Docker Compose
stack. The release workflow publishes the backend and Agent runtime image:

```text
ghcr.io/yespon/prism-os:v0.1.0-alpha.2
```

The image targets `linux/amd64` and `linux/arm64`. It is built from
`backend/Dockerfile`; it is not a self-contained all-in-one image for the
Next.js frontend, nginx, database initialization, LangGraph service, and
optional provisioner. The repository Compose stack remains the canonical full
application deployment path in this alpha.

Use the immutable tag only after the `Publish PrismOS Container` workflow has
completed successfully and the GHCR package is visible to the requesting
identity:

```bash
docker pull ghcr.io/yespon/prism-os:v0.1.0-alpha.2
```

The workflow publishes version/SemVer and SHA traceability metadata and does
not publish a `latest` tag. The package follows the private repository's GHCR
visibility policy, so authentication may be required.

## Validation and known quality debt

Alpha.2 fixes the release-blocking lockfile drift. Its hard runtime release
gates are:

- PrismOS/legacy environment compatibility regression checks;
- locked backend dependency installation and pytest collection; and
- root, production, and development Compose configuration validation.

The frontend installation is still hard-gated by `pnpm install --frozen-lockfile`.
Frontend lint, typecheck, unit tests, and production build are recorded as a
non-blocking quality audit artifact so that the backend/runtime OCI publication
does not imply that the unfinished frontend quality debt has passed. At the
current baseline, those checks still contain known lint, type, test-contract,
and build errors. They must be repaired in their own work before the frontend
can be treated as a release-quality gate.

This release must not be described as a fully passing backend or frontend
release. The backend full suite still contains pre-existing contract failures;
the publish gate checks collection rather than claiming all tests pass.

## Compatibility and security boundaries

New deployments use:

```text
PRISMOS_* → OPSINTECH_* (legacy input) → PrismOS defaults
```

The default new runtime directory is `backend/.prismos`. If it does not exist
and `backend/.opsintech` exists, the resolver can use that existing directory
in place without copying, renaming, deleting, or rewriting it. Back up runtime
data and database volumes before upgrading or changing an explicit path.

The current execution foundation remains the DeerFlow-compatible harness and
LangGraph. The `deerflow` import boundary, existing API routes, database tables
and migrations, and historical data paths remain intentionally unchanged.

This alpha is not a security certification or production isolation guarantee:

- the default local filesystem sandbox executes on the host;
- Docker-socket modes can provide substantial host control;
- Kubernetes provisioner mode requires operator-managed RBAC, quotas, image
  provenance, network policy, and kubeconfig protection; and
- MCP servers, model providers, Skills, plugins, and generated artifacts are
  external trust boundaries.

Review [SECURITY.md](../../SECURITY.md) before enabling untrusted code,
third-party MCP servers, Docker/Kubernetes sandboxing, or external model
providers.

## Roadmap direction

The implementation sequence remains the whitepaper foundation roadmap:

```text
Governance primitives → Task/Run execution lifecycle → Workflow lifecycle
→ Evaluation and observability → Connector/runtime independence → Federation
```

Alpha.2 is a publication-foundation correction, not a claim that these later
layers have already shipped.
