## 构建环境盘点 ✅

关键发现：上游壳已内置 `OCTOP_DESKTOP_URL` 远程模式（跳过便携后端）——第二宿主红线是配置接缝而非重写。本机 Go 1.22 需升 1.25+；Linux 制品可产、Windows 需实测交叉编译、macOS 记差距账本。

## 远程壳改造 ✅

`desktop-shell-fork/`（上游 b6 壳 fork）：
- `boot()` 改为**远程客户端模式**：`PRISMOS_DESKTOP_URL` 必填（`OCTOP_DESKTOP_URL` 兼容）；未设置时显示明确错误而非启动便携后端——第二宿主红线在唯一入口封死
- `stopOctop` 保留为 nil 安全空操作（shutdown 路径）
- 便携下载/升级代码暂留 fork 但从 boot 不可达；远程流程在 linux-amd64 验证后清理
- 源资源提交，`src/build/bin/` 构建产物排除

## PWA 切片 ✅

`manifest.webmanifest`（standalone、PrismOS 品牌）；**offline 缓存刻意后置**——客户端契约要求断线恢复读服务端事实，盲目缓存会违反恢复语义；service worker 作为带过期规则的后续切片。

## linux-amd64 制品首验 ✅

- 制品 17.7MB（Wails v3.0.0-beta.13 / Go 1.27.2 / CGO）
- 构建链：golang.google.cn 下载 Go（proxy.golang.org 超时）→ goproxy.cn 拉模块 → **webkitgtk-6.0 + gtk4 是硬依赖**（webkit2gtk-4.1 不满足，盘点遗漏已补）→ 直接 `go build` 产制品（wails3 CLI 非必需）
- Headless 验证：不设 URL 时红线行为成立（不启动便携后端）；设 `PRISMOS_DESKTOP_URL` 后 waitHealth 通过（`/api/health` 401 属 <500 通过）
- 证据：`evidence/2026-10-19-r4-desktop-build/artifact-verification.md`
